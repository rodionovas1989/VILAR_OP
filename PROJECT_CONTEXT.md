# PROJECT_CONTEXT

## Ветка: feature/stock-documents (активна)

Документная модель движений по запасам и резервам.

### Готово
- Auth: Admin/Admin, шапка, JWT + «Запомнить»
- **Отдельные коллекции и вкладки** на каждый тип документа (9 типов)
- API: `/api/documents/:type/...` — create, post, **repost**, cancel, fulfill
- Регистры: `active_reservations`, `reservation_history`
- Подсистема качества (заглушка)
- Скрипты запуска: `port-guard.ps1`, `restart-all.bat` (защита от дублирования на 3001/5173)
- UI документов: плоская форма, меню «Действия» (сохранить / провести / повторно провести / отменить), RBAC через роли
- Дата и время документа — отдельные поля; в списке и форме — имена пользователей по id (tooltip с id)
- Навигация: при смене раздела скролл контента наверх
- **Роли** (Администрирование): матрица read/create/modify; меню и CrudPage фильтруются по правам
- **Главная**: избранные разделы (☆), per user; колонки = тип объекта, строки = плашки; фильтрация по RBAC
- Списки документов и заказов: цветные бейджи статуса; отбор и сортировка — панель «Отбор и сортировка» (до 2 уровней)
- `ProductionOrderPage` — заказы с модалкой в стиле документов
- Legacy UI «Резервирование (legacy)» убран из меню; backend `reservations` — до этапа RES↔planning

### Следующий этап
- **RES ↔ планирование** (`confirmMaterialPicks`, перепланирование)
- **PRI/PRR ↔ completeOrder** (транзакция)
- Склады списания/выпуска в производстве

### Legacy
- Коллекция `reservations` в backend (planning) — до этапа 2; UI и RBAC-объект убраны
- `stock_documents` — мигрировано в typed-коллекции, файл пустой
