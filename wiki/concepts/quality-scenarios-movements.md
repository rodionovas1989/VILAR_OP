# Concept: сценарии качества = видимые движения

**Инвариант:** любое изменение доступности / типа остатка / места хранения — **только** через обычные складские документы (RCP, TRN, STT, WOF…). Никаких скрытых проводок в сервисе сценариев.

**Сценарий** — автоматическая **последовательность тех же действий**, которые мог бы сделать человек: создать документ(ы) → пользователь видит их в журнале → проведение даёт движения (или сценарий создаёт уже согласованный draft и проводит его **тем же** API post, что UI — без обхода журнала).

Не делать: менять `stock` / регистры качества «внутри» `onLotCreated` без документа; тихий side-effect из LCH/QCM.

**Цель после Q10:** сценарии перенастроить с авто-QCM на документы остатков (например RCP→QI, draft STT). Справочник `lot_qualities` / QCM / `quality_register` — **вывод** (заказчик не опирался; дублируют типы остатка).
