## Как в SAP (Sample Management)

Отдельная сущность **physical sample** (напр. QPRS / drawing QPRN):

| Вид | Смысл |
|-----|--------|
| **Primary** | Отобрано из qty лота / партии |
| **Pooled** | Смесь primary |
| **Reserve** | Архив / контрольная проба (часто до expiry) |

- Создаётся по **sample-drawing procedure** (часто вместе с inspection lot).
- Результаты MIC могут писаться **по пробе** (inspection points).
- **Не** путать с **sampling procedure** (статистика объёма контроля по характеристике).

Qty на складе при этом меняется обычными IM-проводками (sample consumption, transfer). Карточка пробы — про **учёт объекта пробы**, не замена типа остатка UR/QI/Blocked.

## Решение для Vilar

| ID | Роль |
|----|------|
| **Q10** | Типы остатка + движения (STT/TRN…); причины движения. **Без** сущности пробы |
| **Q13** | **Полноценный** отбор проб: сущность пробы (дух QPRS), виды, связь с партией и с документным движением qty, срок/архив по мере необходимости GMP |

Q13 **не** сводится к «TRN на лабораторию + reason» — это лишь складской слой; карточка пробы — отдельный контур.

Зависимости (ориентир): опираться на Q10 (движения qty прозрачны); стык с LCH/Q12 и опц. Q11 — при проектировании плана Q13, не молча.

**Статус:** идея + эта статья. Детальный `docs/plans/…` — после уточнения объёма (primary/reserve, склад lab, списание vs остаток пробы).
