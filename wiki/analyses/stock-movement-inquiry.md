# Разбор: отчёт для расследования движений запасов

Статус: сделано в отчёте «Движения запасов» (`report_stock_movements`, `stockMovementReport.js`). Запрос 2026-10-30: сейчас для разбора приходится вручную смотреть документы, регистры и идентификаторы.

## Что уже есть

| Слой | Что даёт | Чего не хватает для расследования |
|------|----------|-----------------------------------|
| `stock` | Текущий остаток партия × склад | Нет истории, как остаток получился |
| `material_movements` | Журнал дельт: материал, партия, склад, ±количество, документ, серия, заказ, время, статус документа | Экран «Запасы (ист)» — сырой список: нет склада и внутреннего идентификатора партии, тип `issue`/`receipt`, документ не открывается, нет бегущего остатка |
| `production_register` | Аналитика PRI/PRR (серия, заказ, РЦ) | Не складской остаток, параллельный журнал |
| `active_reservations` / `reservation_history` | Резерв RES | RES не меняет `stock` |
| Трассировка документа | Движения одного документа | Старт только из карточки документа, не от партии |
| Отчёт по запасам | Снимок остатка деревом | Не журнал |

Пишут в `material_movements` только реальные дельты остатка (`applyStockDelta`). RES и проведение INV остаток не двигают; INV порождает черновики WOF/PST.

## Предлагаемый отчёт

Отдельный пункт меню, не компоновка «Отчёта по запасам»: зерно другое (событие, не остаток). Один запрос, две компоновки.

**Зерно строки** — одна запись `material_movements`, на экране уже с именами: дата и время, документ (номер и тип), статус документа, склад, материал, партия производителя, идентификатор партии, серия, заказ, количество со знаком, остаток после операции по этой партии на этом складе.

Отборы периода — даты с и по, как у других временных отчётов. Дополнительно хватает любого одного входа: материал, партия (номер или идентификатор), склад, серия, номер документа. Пустой период без других отборов не грузить целиком.

### Компоновка «Журнал»

Плоский список за отбор. Клик по номеру документа открывает уже существующую карточку документа (просмотр), не новый экран. Отменённые движения остаются в списке со статусом документа, чтобы было видно сторно.

### Компоновка «Партия»

Шапка: партия, материал, контрагент, производитель, текущее качество, остатки по складам (это `stock`). Ниже журнал только этой партии с бегущим остатком по складу. Отдельной полосой, не в колонке количества: активный резерв и история RES. `production_register` не второй источник количества: серия и заказ уже лежат на движении; для PRI/PRR достаточно ссылки на заказ.

## Чего не делать

- Не заменять «Запасы (ист)» этим отчётом в том же экране справочника: регистр остаётся техническим, отчёт — рабочим.
- Не смешивать резерв и остаток в одной сумме.
- Не строить историю обходом документов: документ — ссылка со строки журнала, журнал уже записан при проведении.

Excel — те же строки, что на экране. Права — чтение объекта отчёта, запись в регистры не нужна.
