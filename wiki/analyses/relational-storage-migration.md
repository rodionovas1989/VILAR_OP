# Анализ: переход на реляционное хранение (SQLite → PostgreSQL)

Статус: синтез + **есть план**. Обновлено: **2026-11-03**.  
Канон: [`docs/plans/relational-storage-postgres.md`](../../docs/plans/relational-storage-postgres.md).  
ROADMAP: **STOR1** (этап 1), **I1** (этап 2). ADR: [D012](../decisions/D012-relational-then-postgres.md).

## Зачем простыми словами

Сейчас почти все данные — **мешки JSON** в одной таблице SQLite (`collection` + `id` + `data`). Проводки и отчёты собираются в коде Node. Это удобно для пилота, но мешает:

- жёстко запретить два остатка на одну пару «партия + склад»;
- быстро считать срезы и JOIN для ПТО / INT1;
- масштабировать одновременные проведения.

**Цель:** обычные таблицы с колонками и ключами (как во «взрослом» учёте), qty-only без финансов. **СУБД на финише:** PostgreSQL.

## Два этапа

| Этап | Что меняется | Что не меняется сразу |
|------|----------------|------------------------|
| **1. STOR1** | Форма данных внутри файла `.sqlite`: таблицы `stock`, движения, строки документов… | Файл БД, деплой «скопировал sqlite», привычный бэкап файла |
| **2. I1** | Движок: PostgreSQL на ВМ; тот же смысл таблиц | Бизнес-правила GMP / статусы заказа |

Смысл двух шагов: не чинить модель хранения и серверную СУБД **одним** рывком.

## Ключи (самое важное)

- Остаток: **уникально** `(партия, склад)`.
- Резервы и движения ссылаются на заказ / документ / партию / склад.
- Номер документа уникален в рамках типа.
- Регистр качества: одна актуальная строка на партию; характеристики — на пару (партия, характеристика).

Подробные колонки и волны W1–W6 — в плане.

## Риски

Дубли в текущих данных до UNIQUE; «кривой» JSON при выгрузке; cutover без бэкапа; пароль БД в git/wiki. Митигации — audit/ETL checksum, offline sqlite + `pg_dump`, секреты только EnvironmentFile / `local/`.

## Cursor и пилотная ВМ

- Схему, миграции, скрипты и локальный STOR1 — в Cursor на ПК.
- Поставить Postgres и перенести данные **на пилотную ВМ** агент может **по SSH**, если вы дадите доступ и согласие; без SSH — только чеклист для ручного запуска.
- На бой — после отработки в ветке / `main`, с бэкапом и планом отката (вернуть sqlite + прежний релиз).
