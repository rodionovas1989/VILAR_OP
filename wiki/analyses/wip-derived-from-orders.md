# Анализ: аналитическое НЗП из заказов (без цехового склада)

Статус: синтез query / decision. Обновлено: **2026-11-04**.  
Скоуп: qty «в незавершёнке» для отчётов (ПТО / mid-month серия). **Без** финансов и без отдельного qty-регистра НЗП.

Связано: [pto-manual-form](pto-manual-form.md), [sap-mm-pp-comparison](sap-mm-pp-comparison.md), [pri-prr-complete](../entities/pri-prr-complete.md), [order-status-machine](../concepts/order-status-machine.md), G2b [tech-maps-pp-pi-phases](../../docs/plans/tech-maps-pp-pi-phases.md), R10, ROADMAP **R9** / **A3c**, план [order-status-history](../../docs/plans/order-status-history.md).

---

## 1. Решение продукта

Выбрана **модель 2 (как G2b):** фазы → PRI, финал → PRR; отдельный склад «производство» и отдельный qty-слой НЗП **не** вводим.

**«В НЗП» для отчёта** = производный показатель:

> нетто PRI по заказам, которые на дату D ещё **не** завершены (нет PRR / завершения с учётной датой ≤ D).

Это **не** строка в `stock` и не то, что видит INV. В духе SAP: после GI 261 до GR 101 материал «на заказе», не в MARD.

Противоречия с G2b нет: план запрещает **регистр** НЗП, не запрещает **аналитику** по `productionOrderId` на PRI/PRR.

---

## 2. Проблема «серия посередине месяца»

Сейчас (до G2b-b): atomic complete = PRI+PRR в один момент. До complete — только мягкий RES; после — сырьё уже списано и ГП уже на складе. Февральская работа при мартовском complete в отчёте за февраль **не видна**.

После G2b-b: PRI можно провести в феврале, PRR — в марте. Тогда:

- `wip(28.02)` включает февральские PRI открытых заказов;
- в марте при завершении эти qty уходят в «расход на выработку» периода завершения.

---

## 3. Формула (канон для R9)

На дату D, по материалу (партии сворачивать):

`wip(D) = Σ PRI.qty` (нетто с учётом сторно R10), где:

- документ проведён;
- `postingDate ≤ D` (после R10; до R10 — временный суррогат по канону движений);
- заказ на D ещё не завершён: нет PRR с `postingDate ≤ D` (или дата перехода в `завершен` > D).

За период (P0, P1]:

| Показатель | Правило |
|------------|---------|
| Приход в НЗП | PRI с `postingDate` в периоде |
| Выход из НЗП («расход на выработку») | сумма нетто PRI заказов, **завершённых** в периоде (весь PRI заказа, даже если часть была в прошлом месяце) |
| Сдано ГП | PRR в периоде |

**Политика:** выход из НЗП = **завершение заказа**, не «дата каждого PRI». Иначе уравнение остатка НЗП на бланке ПТО разъезжается.

«В сырье» на дату = реконструкция/`stock` по складам сырья (не путать с wip).  
«Загружено» vs «расход» через TRN≠PRI в этой модели **нет** — оба смысла завязаны на PRI и правило периода выше.

## 4. Как похожий отчёт в SAP

Не одна транзакция «ПТО», а сборка:

1. MSEG: 261/262 и 101/102 с BUDAT и номером заказа.
2. COOIS: какие ордера на дату ещё открыты (без полного DLV / до TECO–CLSD — по политике завода).
3. «НЗП qty» ≈ Σ 261 по ещё открытым заказам — аналитика, не MARD.
4. Денежное WIP конца месяца — CO, вне скоупа.
5. Цеховой SLoc — только если завод ведёт физический «у цеха» (у нас MVP без этого).

## 5. Статусы и логи (SAP / Vilar)

SAP **не** пишет статусы всех документов в одну JEST-таблицу: status management — для заказа и подобных объектов; matdoc — отдельные MKPF/MSEG.

| Объект Vilar | Лог смен |
|--------------|----------|
| Складские документы | **A3b** `document_status_log` |
| Производственный заказ | Сейчас только поле на карточке; цель **A3c** `production_order_status_log` |

Для qty-WIP предпочтительны **факты PRI/PRR**. A3c нужен для аудита и честного as-of статуса, не как источник количества.

## 6. Зависимости

| ID | Роль |
|----|------|
| **G2b-b** | Разнесённые PRI/PRR и статус `в работе` — иначе «открытый заказ со списанием» почти не существует |
| **R10** | `postingDate` и сторно-документы для нетто |
| **R9** | Потребитель формулы (реализация позже; статус идея) |
| **A3c** | Мягкая связь (аудит статуса); не блокер R9 |

---

## 7. Границы

- Нет колонки «остаток у цеха» как складского qty без модели цехового склада.
- Нет различия TRN-загрузка vs PRI-выработка.
- До внедрения A3c as-of статуса заказа неполный; не подменять им `postingDate`.
- Регенерация растворителей и т.п. — отдельные движения, не формула WIP.
