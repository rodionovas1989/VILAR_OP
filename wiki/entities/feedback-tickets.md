# Entity: обратная связь (feedback / тикеты)

Внутренние обращения пользователей (не внешний helpdesk).

- Категории: понравилось / улучшить / ошибка / вопрос.
- Статусы: новый → в работе → закрыт | отклонён.
- Номер: `FB-YYYY-MM-DD-NNNNN` (последовательность по дате).
- Автор видит свои; модератор (`seeAll`) — все. ObjectId: `admin_feedback`.

**API:** `/api/feedback`  
**Код:** `backend/src/services/feedback.js`, UI `FeedbackPage`  
**Не путать** с `docs/CHANGELOG.md` / «Что нового».

**Процесс обработки (с 2026-09-07):** выгрузка «в работе» с ВМ → 1 тикет = 1 ветка → merge в `main` → деплой на пилот → **закрытие тикетов в sqlite на ВМ** вместе с выкатом (не ждать ручного UI). Скрипт закрытия — только в `local/` (не в git).

## Вход агента

Запрос «новые тикеты», номер FB-… или обратная связь:

1. Не читать `backend/data/vilar.sqlite` — это локальная копия, не пилот.
2. Выгрузить с пилота скриптом `local/dump-feedback-open.py` (как подключаться — шпаргалка в `local/`, в wiki не копировать). Брать статусы «новый» и «в работе», сверить номера с обработанными ниже.
3. В PowerShell не прокидывать текст скрипта с кириллицей через пайп: фильтр статусов молча пустеет, хотя счётчик в базе верный. Запускать файл на ВМ.
4. Сначала разбор и проект, потом код. **1 тикет = 1 ветка** от `main`.
5. Закрытие на пилоте — `local/close-feedback-tickets.py` только вместе с выкатом, не в ветке фичи.
