# D010 — Одна партия на нескольких складах

**Контекст:** GMP требует **одну партию** сырья на компонент серии ([gmp-one-lot-per-component](../concepts/gmp-one-lot-per-component.md)). Физически одна партия может лежать на **нескольких складах**.

## Целевой путь (G13 / D015)

**Split RES** одной партии по складам + **Pull list** (TRN + переназначение RES на склад отпуска / Производство).  
Канон: [docs/plans/reservation-pull-list-staging.md](../../docs/plans/reservation-pull-list-staging.md), ADR [D015](D015-reservation-pull-list-staging.md).  
ROADMAP **G8** (авто-split) — **superseded by G13**.

## Interim (до внедрения G13-b/c) — как в коде сейчас

- Подбор и резерв смотрят `freeQty` **на выбранном складе**, не суммируют остаток партии по всем складам.
- На позицию спецификации — **одна** строка подбора; две строки на одну позицию (даже с одним `lotId` и разными складами) отклоняются.
- N RES/PRI ([D009](D009-multi-warehouse-pri.md)) — когда **разные** позиции заказа списываются с разных складов, а не когда одна позиция «размазана» по складам.
- Итог: партия 10+10 на двух складах при потребности 15 → подбор/резерв **не проходят**.
- Обход: консолидация документом **TRN** на нужный склад **до** резерва.

## Исторические варианты (закрыты выбором G13)

| Вариант | Суть | Итог |
|---------|------|------|
| A. Авто-аллокация / split | UI одна партия; бэкенд режет qty по складам → N RES с одним `lotId` | **Взято в G13** |
| B. TRN вручную | Сначала перемещение, затем резерв | Interim до G13 |
| C. Ручной split строк | Две строки подбора, один lot | Поглощено A/G13 |
| D. Логический склад | Резерв виртуально | Отклонён |

**Не путать с D009:** D009 — разные материалы/строки с разных складов → N документов. D010/G13 — одна позиция / одна партия, остаток разнесён по складам.
