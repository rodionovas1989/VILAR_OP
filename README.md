# Vilar OP — оперативное планирование производства

Система оперативного планирования серий препаратов и резервирования партий сырья для фармпредприятия (GMP).

## Стек

| Слой | Технология | Зачем |
|------|------------|--------|
| Frontend | React + Vite + TypeScript | Веб-интерфейсы CRUD и рабочий стол планирования |
| Backend | Node.js + Express | REST API, Excel через `exceljs` |
| Данные | SQLite (`backend/data/vilar.sqlite`) через `node:sqlite` | WAL + транзакции; без Visual Studio / native-сборки |
| Gantt | [Apache ECharts](https://echarts.apache.org/) (Apache-2.0) | Загрузка РЦ: дорожки = рабочие центры, параллельные заказы |

## Возможности

- Справочники: материалы, спецификации, контрагенты, партии, серии, РЦ, **склады**, плановые объёмы; отборы; иконки действий
- Запасы (с привязкой к складу), резервирование, движения материалов
- **Заказы на производство**: план и факт выпуска/состава
- Рабочий стол планирования: подбор заказов → сырья → Гант → иерархия → матрица
- **Производство** → управление заказами: факт выпуска, замена партий, завершение по факту
- **Администрирование**: руководство пользователя (инструкция + вопросы и ответы); экспорт справочников в Excel; пользователи; обратная связь (тикеты)
- **Отчеты**: выпущенные серии; запасы (склад → материал → партия); качество запасов (материал → партия → склад); история качеств; Excel и печать
- **Складские документы** (ветка `feature/stock-documents`): приёмка, резервирование, регистры; см. `docs/STOCK_DOCUMENTS_SPEC.md`
- **Управление качеством**: справочник качеств партий (разрешения Годен / Условно годен / Не годен), единый документ, регистры; влияет на планирование и закрытие заказа
- Полоска **последних открытых** объектов под шапкой (до 8; просмотр/изменение)
- **Политика ПДн** и принятие при первом входе; уведомление о cookie-сессии; см. `docs/LEGAL_PDN.md`
- Правила GMP: `docs/GMP_SERIES_RULES.md`

## Для пользователя без опыта IT

В папке проекта только эти файлы запуска (английские имена — так надо для Windows):

1. **`install.bat`** — один раз (ставит библиотеки; демо-данные — **только если ещё нет** файла базы)
2. **`start-all.bat`** — каждый день (бэкенд + интерфейс; **не** пересоздаёт данные; не запустит дубликат, если порты 3001/5173 заняты)
3. **`restart-all.bat`** — остановить старые процессы и запустить заново
4. **`backup.bat`** — копия базы в папку `backups\`

Или по отдельности: **`start-backend.bat`**, затем **`start-frontend.bat`**.

В браузере: `http://localhost:5173`

Нужен Node.js **22+**: портативный в `.tools\node` или LTS 22 с [nodejs.org](https://nodejs.org). Visual Studio не требуется.

`start-all.bat` **не** запускает seed. Повторный `install.bat` при уже существующей базе `backend\data\vilar.sqlite` тоже **не** затирает данные. Пересборка демо только вручную: `cd backend && npm run seed`.

## Быстрый старт (из командной строки)

Из **корня** проекта:

```bash
npm run setup          # install backend+frontend + seed (если нет sqlite)
npm run backend        # API http://localhost:3001
npm run frontend       # UI  http://localhost:5173  (второй терминал)
```

Классический способ:

```bash
cd backend && npm install && npm run seed && npm run dev
cd frontend && npm install && npm run dev
```

Автотесты цепочки документов (изолированная sqlite, рабочие данные не трогают):

```bash
npm test
```
