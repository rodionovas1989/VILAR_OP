# Vilar OP — оперативное планирование производства

Система оперативного планирования серий препаратов и резервирования партий сырья для фармпредприятия (GMP).

## Стек

| Слой | Технология | Зачем |
|------|------------|--------|
| Frontend | React + Vite + TypeScript | Веб-интерфейсы CRUD и рабочий стол планирования |
| Backend | Node.js + Express | REST API, файловое хранилище JSON, Excel через `exceljs` |
| Данные | JSON-файлы в `backend/data/` | Быстрый старт; перспектива — SQL (SQLite/Postgres) без смены контракта API |
| Gantt | [Apache ECharts](https://echarts.apache.org/) (Apache-2.0) | Загрузка РЦ: дорожки = рабочие центры, параллельные заказы |

## Возможности

- Справочники: материалы, спецификации, контрагенты, партии, серии, РЦ, **склады**, плановые объёмы; отборы; иконки действий
- Запасы (с привязкой к складу), резервирование, движения материалов
- **Заказы на производство**: план и факт выпуска/состава
- Рабочий стол планирования: подбор заказов → сырья → Гант → иерархия → матрица
- **Производство** → управление заказами: факт выпуска, замена партий, завершение по факту
- **Администрирование**: экспорт справочников в Excel; пользователи
- **Складские документы** (ветка `feature/stock-documents`): приёмка, резервирование, регистры; см. `docs/STOCK_DOCUMENTS_SPEC.md`
- **Управление качеством** (заглушка): документы и регистры без связи с планированием
- Правила GMP: `docs/GMP_SERIES_RULES.md`

## Для пользователя без опыта IT

В папке проекта только эти файлы запуска (английские имена — так надо для Windows):

1. **`install.bat`** — один раз (ставит библиотеки и демо-данные)
2. **`start-all.bat`** — каждый день (бэкенд + интерфейс; не запустит дубликат, если порты 3001/5173 заняты)
3. **`restart-all.bat`** — остановить старые процессы и запустить заново

Или по отдельности: **`start-backend.bat`**, затем **`start-frontend.bat`**.

В браузере: `http://localhost:5173`

Нужен Node.js: портативный в `.tools\node` или с [nodejs.org](https://nodejs.org) (LTS).

## Быстрый старт (из командной строки)

Из **корня** проекта:

```bash
npm run setup          # install backend+frontend + seed
npm run backend        # API http://localhost:3001
npm run frontend       # UI  http://localhost:5173  (второй терминал)
```

Классический способ:

```bash
cd backend && npm install && npm run seed && npm run dev
cd frontend && npm install && npm run dev
```
