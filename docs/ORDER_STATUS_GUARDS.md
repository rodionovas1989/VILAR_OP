# Guards статусов заказа

«Guard» — проверка **до** действия: если статус заказа не тот, операция запрещена. Иначе можно, например, заново зарезервировать уже завершённый заказ или списать сырьё дважды.

## Статусы

| Статус | Смысл |
|--------|--------|
| `новый` | Черновик плана. Нет RES. |
| `спланирован` | Есть **проведённый** документ резервирования (RES). Сырьё занято в `active_reservations`. |
| `завершен` | Проведены PRI (списание) и PRR (выпуск ГП), RES в статусе **выполнен**. |
| `отменен` | Заказ снят. Открытый RES отменён. |

## Кто что может

| Действие | Откуда | Допустимый статус | Что происходит |
|----------|--------|-------------------|----------------|
| Подбор заказов (вкладка 1) | только `новый` | без изменений | |
| Подтвердить материалы | `новый` или `спланирован` (переплан) | Создаётся/заменяется RES [posted], заказ → `спланирован` |
| Сохранить факт | только `спланирован` | Пишет actualQuantity / actualLines |
| Завершить производство | только `спланирован` | PRI + PRR [posted], RES [fulfilled], заказ → `завершен` |
| Отменить заказ | `новый` или `спланирован` | RES [cancelled] если был, заказ → `отменен` |
| Завершить уже `завершен` | **запрещено** | Иначе повторное списание |
| Отменить `завершен` | **запрещено** | Нужна отдельная процедура сторно PRI/PRR |

## Документы вокруг заказа

```
новый
  → confirm picks → RES posted + active_reservations → спланирован
  → cancel → отменен (документов нет)

спланирован
  → confirm picks снова → старый RES cancelled, новый RES posted (переплан)
  → complete → PRI posted + PRR posted + RES fulfilled → завершен
  → cancel → RES cancelled → отменен
```

Перепланирование не трогает завершённые заказы: guard не пустит.
