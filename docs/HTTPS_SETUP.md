# HTTPS на пилотной ВМ (домен + Let’s Encrypt)

Контекст: ВМ Yandex Cloud `vilar-op`, сейчас UI/API на `http://51.250.73.169:3001`.  
Rate limit login уже на ВМ — **HTTPS можно делать следующим шагом**.

Цель: `https://ваш-домен` (порт 443) → nginx → приложение на `127.0.0.1:3001`.  
Снаружи порт **3001 закрыть**; наружу только **80** (проверка сертификата) и **443**.

---

## 1. Где взять домен

Нужно имя вида `op.example.ru` или `vilar-op.example.ru`. Для Let’s Encrypt **бесплатный сертификат на «голый» IP не выдают** — нужен домен.

| Где купить / зарегистрировать | Комментарий |
|-------------------------------|-------------|
| [reg.ru](https://www.reg.ru/) | Удобно в РФ, карта, .ru / .рф |
| [timeweb.cloud](https://timeweb.cloud/) / Timeweb | Домены + DNS |
| [nic.ru](https://www.nic.ru/) | Классика .ru |
| [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/) | Часто дешевле; DNS удобный |
| [Beget](https://beget.com/), [SprintHost](https://sprinthost.ru/) и др. | Аналогично |

**Что купить для пилота**
- Недорогое имя: `.ru`, `.online`, `.site` и т.п. (часто от ~200–500 ₽/год).
- Не обязательно «красивое» корпоративное — для пилота хватит `vilar-op-pilot.ru` или поддомен, если домен уже есть у заказчика.

**Если домен уже есть у заказчика**  
Попросите у их IT: создать DNS-запись типа **A** на IP ВМ (см. ниже). Регистратор тогда не нужен вам.

**Поддомен**  
Если есть `company.ru` — достаточно `op.company.ru` (A-запись), отдельный домен покупать не обязательно.

---

## 2. Зафиксировать IP ВМ (важно)

Сейчас публичный IP может быть **динамическим**. Для DNS нужен **постоянный** адрес.

В [консоли Yandex Cloud](https://console.yandex.cloud):
1. **VPC → IP-адреса** → зарезервировать статический публичный IPv4 (или «сделать статическим» у текущего адреса ВМ).
2. Привязать его к ВМ `vilar-op` (если ещё не привязан).
3. Записать адрес (например тот же `51.250.73.169` или новый).

Дальше все DNS A-записи указывают **только на этот** IP.

---

## 3. DNS: связать домен с ВМ

В панели регистратора / DNS (или у заказчика):

| Тип | Имя (host) | Значение | TTL |
|-----|------------|----------|-----|
| **A** | `@` (корень) или `op` / `vilar-op` | `IP_ВМ` | 300–3600 |

Пример: домен `example.ru`, поддомен `op` → открывать `https://op.example.ru`.

Проверка с ПК (через 5–30 минут после сохранения):

```powershell
nslookup op.example.ru
```

Должен вернуться IP ВМ. Пока не совпадает — **не** запускайте certbot (сертификат не выдадут).

---

## 4. Открыть порты 80 и 443

**Группа безопасности** ВМ (Yandex Cloud → VPC → Группы безопасности):
- входящий TCP **80** с `0.0.0.0/0`
- входящий TCP **443** с `0.0.0.0/0`
- **22** оставить для SSH
- **3001** после перехода на HTTPS — **убрать** из внешнего доступа (или закрыть в ufw)

**На ВМ (ufw), ориентир:**

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 22/tcp
# после успешного HTTPS:
# sudo ufw delete allow 3001/tcp
# (приложение слушает только localhost)
sudo ufw status
```

## 5. Nginx + Let’s Encrypt (на ВМ)

Краткий порядок (выполняет админ по SSH; детали можно сделать вместе после появления домена):

1. Установить `nginx` и `certbot` (`python3-certbot-nginx`).
2. Сделать server block: `server_name ваш.домен;` → `proxy_pass http://127.0.0.1:3001;`
3. `sudo certbot --nginx -d ваш.домен` — получит сертификат и включит HTTPS.
4. Редирект HTTP → HTTPS (certbot обычно предлагает сам).
5. Автообновление сертификата: `certbot.timer` / cron (в Ubuntu обычно уже есть).

Прокси должен передавать заголовки `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`.

---

## 6. Настройки приложения после HTTPS

В systemd `vilar-op` и при сборке фронта:

| Параметр | Значение |
|----------|----------|
| `CORS_ORIGIN` | `https://ваш.домен` |
| `TRUST_PROXY` | `1` (rate limit и IP за nginx) |
| Слушать | лучше `127.0.0.1:3001` (не снаружи) |
| Сборка UI | `VITE_API_URL=https://ваш.домен/api` → `npm run build` в `frontend` |
| URL для пользователей | **только** `https://ваш.домен` (без `:3001`) |

Перезапуск: `sudo systemctl restart vilar-op` (+ nginx уже поднят).

---

## 7. Проверка

1. `https://ваш.домен` — замок в браузере, экран «Вход».
2. Login Admin — успех.
3. `http://ваш.домен` — редирект на https.
4. `http://IP:3001` снаружи — **не** должен открываться (закрыт firewall).

---

## 8. Без домена (временно, не рекомендуется)

Самоподписанный сертификат: браузер будет предупреждать «недоверенный». Для заказчика плохо. Для своей отладки — допустимо, но Let’s Encrypt + домен предпочтительнее.

---

## Что принести агенту / админу, когда будете готовы

1. Имя хоста: например `op.example.ru`
2. Подтверждение: `nslookup` показывает IP ВМ
3. Статический IP зафиксирован
4. Порты 80/443 открыты в SG

Дальше можно настроить nginx + certbot + systemd/`VITE_API_URL` на ВМ за один сеанс.
