# Правовая информация и персональные данные (пилот Vilar OP)

Документ для аудита и заказчика. Тексты UI: `frontend/src/content/legal/`.  
Версия Политики в коде: **2026-08-15** (`PDN_POLICY_VERSION` — синхронно FE и `backend/src/constants/legal.js`).

## Модель доступа

- Самостоятельная регистрация **не** предусмотрена.
- Учётную запись создаёт **администратор**.
- Ознакомление с Политикой ПДн фиксируется при **первом входе** (или при смене версии): поля пользователя `pdnAcceptedAt`, `pdnPolicyVersion`.
- Без принятия актуальной версии рабочий интерфейс недоступен (только экран принятия / выход).

## Оператор (шаблон)

В Политике указано: **«Организация-оператор пилота»** (`OPERATOR_NAME` в `frontend/src/content/legal/constants.ts`).  
Перед промышленной эксплуатацией подставьте юрлицо, адрес и контакт ответственного за ПДн.

## Сроки хранения (заложены в продукт)

| Данные | Срок |
|--------|------|
| Журнал входов (`login_audit.jsonl`) | 90 суток, автоочистка |
| Чат | последние 200 сообщений |
| Cookie-сессия | ~8 ч; с «Запомнить» — до 30 суток |

## Чеклист организации-оператора (вне кода)

1. Заполнить юрлицо и контакт в `OPERATOR_NAME` / `OPERATOR_CONTACT` (или согласовать текст с юристом и обновить версию Политики).
2. Локальный акт: ответственный за ПДн; ИСПДн «Vilar OP (пилот)».
3. При выдаче логина — уведомить сотрудника о Политике (она также в Системе: Администрирование → Политика ПДн).
4. С юристом: необходимость уведомления Роскомнадзора.
5. Не публиковать боевую sqlite, пароли, `auth_secret` в открытый GitHub.

## Дисклеймер продукта

Система — внутреннее оперативное планирование производства.  
**Не** является медицинским изделием и **не** заменяет госреестры ЛП, лицензирование и валидацию на площадке.

## API

- `POST /api/auth/accept-pdn` `{ policyVersion }` — только для текущего пользователя; версия должна совпадать с серверной.
