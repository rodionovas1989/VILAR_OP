# Частичное сторно по строкам (упрощённый план)

Зависит от **R10** ([storno-stock-documents.md](storno-stock-documents.md)): сначала полный сторно-документ B.

## Цель

Как **Item OK** в SAP MIGO Cancellation: сторнировать **не все** строки исходного документа A, а выбранное подмножество. Каждая выбранная строка откатывается **целиком** (qty строки не дробим).

## Вне скоупа R11

- Частичное **количество внутри одной строки** (в SAP чаще другой процесс / return delivery).
- RES / INV / QCM.

## UX (черновик)

1. На A (posted, ещё не полностью reversed): «Сторно…» → UI выбора строк (чекбоксы).
2. Создать черновик B только с выбранными строками (обратный смысл qty / TRN swap).
3. Пользователь проводит B (как в R10).
4. A: если сторнированы **все** строки — статус `reversed`; если часть — статус остаётся `posted` + признак «частично сторнирован» (поле или derived по сумме B).

## Данные

- Те же `reverses_document_id` / `is_reversal` на B.
- На строках B: `reverses_line_id` → id строки A (≈ SMBLP).
- Запрет: повторно сторнировать уже полностью покрытую строку A другим posted B.
- Несколько частичных B на один A — допустимы, пока строки не пересекаются.

## Риски

| Риск | Заметка |
|------|---------|
| Два частичных B на пересекающиеся строки | Серверный запрет по `reverses_line_id` |
| TRN / PRI многосклад | Копировать складские поля выбранных строк как в R10 |
| Отчёты | Без изменений канона `postingDate` (R10) |
| STOR1 | Колонка `reverses_line_id` на `document_lines` при W2 |

## Порядок относительно R10

1. R10 в коде (полный B).  
2. R11: UI выбора строк + `reverses_line_id` + частичный статус A.

Детальный дизайн UI/API — при старте реализации R11; этот файл — чтобы пункт не потерялся в ROADMAP.
